    REMOTE MANAGEMENT
    Control a router at another location
    Connect this computer to the site's management VPN, then enter the router's reachable IPv4 address. A public IPv4 address also works with encrypted services when inbound access is configured.
    Next, enter router credentials and a trusted certificate fingerprint when needed. Saved locations let you switch sites. All existing dashboard, voucher and User Manager controls use this connection.
    Reachability comes first
    Set up a management VPN on the router or a gateway at the site. Starlink connections behind carrier NAT need an outbound VPN path; entering the public address alone will not provide access. This app does not install a VPN or expose management ports.
    Use the dashboard from your phone
    Run the backend with HTTPS bound to its private LAN/VPN IP and a trusted certificate. Open its private launch URL over the same VPN. Keep the backend running; owner devices share one active router.
    python3 server.py --listen 10.20.0.2 --tls-cert server.crt --tls-key server.key
    Replace the example IP with an address assigned to the backend computer. Read remote browser setup.
    

    ROUTEROS v7 RADIUS
    User Manager
    Manage RADIUS users separately from local hotspot vouchers. The matching user-manager package must already be installed. Changes below affect the connected router.
    First setup walkthrough
    1. Back up RouterOS and the separate User Manager database. Check licence limits, storage and synchronized time.
    2. In Service settings, enable the service and use-profiles.
    3. Create a RADIUS router client and Router RADIUS client with the same shared secret. Suggested loopback settings apply only when Hotspot and User Manager are on this router.
    4. Enable accounting and use-radius on the correct Hotspot server profile. Enable incoming disconnect requests only after restricting their reachability to trusted RADIUS servers.
    5. Create a profile (for example first-auth, 1d / 3d / 7d / 28d), create speed/data/uptime limits, then link them using Profile limit assignments.
    6. Create a user, then assign its profile. For PIN login, enter the same PIN as username and password.
    7. Test one login and check session accounting before creating more users. Existing local usernames can take precedence over RADIUS accounts.
    Profiles can affect many users. Native RADIUS validity differs from the local-ticket next-day-startup expiry policy.
    Blank fields are omitted. Passwords and shared secrets are redacted from previews and journals. RouterOS validates service-specific values.
    Load User Manager to begin.

    FIRST CONNECTION
    Prepare once. Then use the wizard.
    Connect this computer over Ethernet or Wi-Fi to a trusted router management LAN. Enter the router’s local IP, username and password, then select its enabled service.
    1. Prepare once. Save a router backup and export. The selected service must already be enabled and reachable through the router firewall. A guest hotspot connection may require login or a permitted management path.
    2. Choose a service. API uses port 8728; API-SSL uses 8729; HTTP REST uses 80; HTTPS REST uses 443. Custom ports are supported. Plain API and HTTP are restricted to private LAN addresses. Use encrypted services on untrusted networks.
    3. Prepare a user. A dedicated account needs read/write and the api or rest-api policy for its selected service. Expiry automation may need additional script permissions; see EXPIRY.md.
    4. Connect here. TLS services need a trusted certificate or an independently verified SHA-256 certificate fingerprint. The app does not silently fall back between encrypted and unencrypted services.
    5. Choose your scenario. Inspect the detected interfaces, build a plan, read the operations, and apply after confirming your backup.
    Backup & restore application data
    Back up all profile prices, templates, voucher archives, sales records and saved location settings. Backups contain readable voucher passwords; store them privately. Router credentials, Paystack keys and payment orders are excluded. Restore merges files and replaces matching files, retaining a recovery copy on this computer.
    What this pilot includes
    An owner dashboard, router-recorded first login for tracked tickets, five expiry modes, optional HTTPS phone access, and one router connection at a time, local-user hotspot profiles, two spare-port network setups, random PIN vouchers, printing, CSV export, account disabling with cookie/session cleanup, and an additive change journal.
    Scope and compatibility
    Built for RouterOS v7 API and REST services. RouterOS 7.24.2 compatibility is unverified until hardware acceptance testing. No automatic RouterOS upgrade, router reset, multi-WAN, PPPoE provisioning, Wi-Fi driver configuration, User Manager migration, native mobile app or remote multi-user hosting is included.
    Windows, macOS and Linux can run the Python application. Phones can open the mobile web dashboard when the computer runs the optional HTTPS LAN/VPN mode. The computer remains the backend host. See MOBILE.md. Default access remains this computer only.
